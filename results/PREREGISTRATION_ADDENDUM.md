# 预注册附页：对"跨设备反转"论点的自我反证（写于实验之前，2026-10-20）

> 这一页记录的是一次**否决**。我在推敲 P2/P4 时发现原论点有逻辑漏洞，若不在实验前修掉，
> 12 周后拿到的会是一个被审稿人一击即破的故事。记录下来，是为了让后续所有工作建立在
> 站得住的 claim 上，也让审稿人看到我们自己做对抗性检验。

## 1. 原论点

> "4060 与 Jetson 的 roofline 交叉点 $b^*$ 不同（124 vs 预测 150–280），
> 因此同一工作点落在不同 regime，最优权重/KV 分配**反转**。"

## 2. 反证过程（三步，每步都可被复核）

### 第 2.1 步：prefill 的有效 batch 是 prompt 长度，不是 1

对 $L=32$k 的 prompt，prefill batch = 32768，**两机都远高于各自的 $b^*$**。
→ 长 prompt 场景下，两机的 prefill **都是算力受限**，$b^*$ 的差异不产生 regime 差异。

$b^*$ 只在 **$L \lesssim b^*$（约 124–280 token 的短 prompt）** 时才区分两机。这是一个很窄、且不是主流的窗口。

### 第 2.2 步：decode 的时间模型在两机上同构

$$ T_{decode} = \frac{W + KV(L)}{B_{eff}} $$

对两机都是"字节除以带宽"。因此给定同一组（误差 vs 字节）帕累托点，**两机选出同一个点**。
→ decode 侧不存在反转，只存在绝对速度差异。

### 第 2.3 步：$\eta_c$ 的量级可能不足以产生反转

bitsandbytes 的 nf4 是"4bit 存储 + dequant 到 fp16 + fp16 tensor-core matmul"。
dequant 的代价是 $O(W)$，与 batch 无关；matmul 代价是 $O(\text{batch} \cdot W)$。
→ **batch 越大，dequant 越被摊薄，$\eta_c(\text{nf4}) \to 1$**。

所以 P2（$\eta_c \le 0.85$）在长 prompt（大 batch）下**很可能不成立**。
若 $\eta_c \approx 1$，则"低位宽吃算力"这一反转机制**根本不存在**。

## 3. 结论：原论点站不住，必须换

三条独立的反证指向同一结论：**"跨设备反转"缺乏物理基础，作为主结论是脆弱的。**

保留它作为主结论的风险：审稿人只需问一句"你的 prefill batch 是多少？"就能拆掉整篇论文。

## 4. 换上的主结论（更强、且已由实测数字支撑）

> **在 8GB 设备上，长上下文的瓶颈是 KV cache 而非权重；KV 在 32k 时是权重的 2.7–17 倍，
> 而整个量化文献把比特全押在权重上。因此真正的分配问题是"权重/KV 预算分配"，
> 且最优解随工作负载的 prefill/decode 混合比 $\alpha$ 改变——同一模型在 RAG（prefill 主导）
> 与流式对话（decode 主导）下需要不同的分配方案。**

支撑证据（全部已实测或已从真实 config 算出）：

| 证据 | 值 | 状态 |
|---|---|---|
| KV/权重 比 @32k, Qwen3-4B | 4.83 / 1.82 = **2.7×** | 已算（真实 config） |
| KV/权重 比 @32k, Qwen3-0.6B | 3.76 / 0.22 = **17×** | 已算 |
| Qwen3-8B @4bit+32k | 8.93 GB > 8 GB → **装不下** | 已算 |
| 文献中把 KV 纳入分配决策的比例 | 108 篇里几乎为零 | `lit/GAP_MATRIX.md` §2 |
| 文献中同时 regime-aware 且 budget-aware | **1 篇**（且仅权重） | 同上 |

## 5. 反转降级为"待检验假设"，并改写判定条件

- P4 保留，但不再是主结论；判为 **exploratory**，失败**不影响**论文成立。
- 新增 P6（新的主检验）：
  > 在固定 8GB、$L=32$k 下，$\alpha$ 从 0.1（流式）扫到 0.9（RAG），
  > 最优分配的 KV 位宽单调性应发生方向变化，且该变化在两机上**都可观测**。
  这是**同一设备内**的 $\alpha$ 依赖，不依赖脆弱的跨设备假设。
- 新增 P7：
  > 只用权重量化（Q4_K_M 等主流做法）在 32k 上下文下**无法**在 8GB 上跑通 Qwen3-8B；
  > 必须把 KV 纳入分配。这是可行性级别的强结论。

## 6. 由此带来的实验设计改动（立即生效）

1. **4B/8B 的优先级上升**：主结论依赖 KV 占比，模型越小权重占比越低、结论越"太容易"。
   但受下载速度限制（0.23 MB/s），先做 0.6B 打通流水线，再上 4B。
2. **必须测 $\alpha$ 的真实取值**：用 TTFT/TPOT 的实测占比反推 RAG 与流式对话的 $\alpha$，
   不能拍脑袋设 0.9/0.1。
3. **必须报告 $\eta_c$ 的 batch 依赖曲线**（$\eta_c$ vs batch），这本身就是一个有价值的发现：
   "低位宽的算力惩罚在大 batch 下消失"——若成立，它终结了反转假说；
   若不成立（$\eta_c$ 持续 < 1），反转假说复活。**两种结果都可发表**。
4. **跨设备对比保留但降级**为"同一 $\alpha$ 下两机的绝对性能与可行性边界差异"。
