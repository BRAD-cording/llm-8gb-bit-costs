# BUG: 分组量化的轴错了（影响所有历史权重侧数字）

发现时间：2026-10-20 18:0x
发现途径：对抗性测试里出现"分组越细误差越大"，违反理论 → 追查到 `_group_view`

## 1. 缺陷

```python
def _group_view(w, group_size, dim=-1):
    shape = list(w.shape)
    shape[dim] = size // group_size
    shape.insert(dim + 1, group_size)   # ← dim=-1 时 dim+1 == 0
    return w.reshape(shape)
```

`dim=-1` 时 `insert(0, g)` 把分组轴插到了**最前面**，而 `shape[-1]` 已被改成 `n//g`。
于是量化沿错误的轴进行，结果 reshape 回原形状后仍然形状正确——**bug 完全不可见**，
只是量化分组是交错的而非连续的。

## 2. 症状（唯一能发现它的地方）

对含离群值的合成权重：

| g | 修复前 rel_err | 修复后 rel_err |
|---|---|---|
| 128 | 0.089 | 0.318 |
| 64 | 0.125 | 0.240 |
| 32 | 0.173 | 0.173 |
| 16 | 0.240 | 0.125 |

修复前**单调变差**（违反"分组越细越准"），修复后单调变好。修复后 g=128 反而更差
（0.318）——说明旧代码在 g=128 时的"好成绩"是错误轴给出的巧合。

## 5. 对结论的影响

**方向不变、幅度变大**：KV 仍是最便宜的一侧。但两件事必须写清楚：

1. 修 bug 后权重端明显更差（32% 而非 9%），这让"KV 更便宜"看起来更强——
   但这是**因为我的权重量化器是朴素 RTN**，而 GPTQ/AWQ 在 4-bit 上远好于此。
   所以不能拿 32% 去和 KV 的 5.6% 比。
2. 真正公平的对比是"同等强度的量化器"：最强调参下权重 6.87% vs KV 5.58%，边际仅 1.23×。
   **结论只能说到"KV 不比权重更脆弱"这一步**，不能说"KV 一定更便宜"。

## 6. 教训（写进 artifact）

一个只在"数字反常"时才暴露的 bug，如果不去查"分组越细为什么更差"，会一路进论文。
对抗性测试的价值不仅在于检验结论，还在于**它是最先让异常显形的地方**。
