# GPTQ：单层通过、整模型失败（未用于论文）

> 2026-10-21。`src/quant/gptq.py`、`src/eval/gptq_weights.py`、`experiments/check_gptq_layer.py`

## 1. 动机

论文的强度匹配检验用的是我自己实现的 AWQ 式激活缩放。审稿人可以说"你的 AWQ 不如官方强"。
GPTQ 是**二阶（Hessian）**机制，与激活缩放完全不同。如果排序在 GPTQ 下也成立，
结论就不再依赖任何单一量化器家族——这正是 Q1 与 Q2 之间那条线。

## 2. 实现

标准 OBQ 误差反馈：`H = XᵀX` 加阻尼 → Cholesky 求逆 → 逐列量化，
`err = (W[:,j] - q_j)/Hinv[j,j]`，`W[:,j+1:] -= err · Hinv[j,j+1:]`。
未实现 dynamic clamping 与 act-order（若使用会如实说明）。

## 3. 结果：单层很好，整模型崩

**单层、真实激活（`model.layers.0.mlp.down_proj`，1.7B，W 2048×6144）**

| 分组 | RTN 输出误差 | GPTQ | 改善 |
|---|---|---|---|
| g=16 | 3.04e-04 | 6.69e-06 | **45×** |
| g=128 | 6.08e-04 | 1.21e-05 | **50×** |

**整模型（28 个评估窗口，与强度表同协议）**

| 模型 / 分组 | RTN | GPTQ | 结论 |
|---|---|---|---|
| 0.6B / g16 | +11.73% | **+4.07%** | 正常，优于 RTN |
| 0.6B / g128 | +34.71% | +15.19% | 正常 |
| **1.7B / g128** | +11.45% | **+37.70%** | **反常，比 RTN 差 3 倍** |
| 1.7B / g16 | +6.01% | +5.58% | 几乎无改善 |

## 4. 已排除的原因

1. **不是激活污染**：改成在原始 fp16 模型上一次性收集全部层激活后再量化（标准做法），
   1.7B 仍为 +37.70%。
2. **不是分块问题**：block=4/8、逐层收集、一次性收集，三种都试过。
3. **不是实现错误**：单层在真实激活上比 RTN 好 45–50×。

## 5. 未排除的假设

- **误差累积**：每层单独更优，但 196 层复合后可能方向相反。未做"只量化前 k 层"的扫描来验证。
- **分组尺度在误差反馈下失配**：我的组尺度取自原始权重，误差反馈会让权重漂出原网格，
  `clamp(0, qmax)` 饱和放大误差。官方实现用 dynamic clamping 处理这一点，我没有实现。
- **1.7B 特有**：0.6B 正常、1.7B 反常，可能与层宽（6144）或离群值分布有关，未查。

## 6. 处理决定

**不把 GPTQ 数字写进论文。** 一个连"必须优于 RTN"这个必要条件都不满足的实现，
产出的任何比较都不可信；而把它写成"GPTQ 也不改变结论"会是编造。

论文现有证据（自实现 AWQ + KIVI，两模型三强度档，3.2–14.3×）不受影响。

## 7. 下一步选项

2. 实现 dynamic clamping 后重测 1.7B。
