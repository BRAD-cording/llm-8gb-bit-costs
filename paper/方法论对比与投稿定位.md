## 一、核心贡献(不在多而在精,DOKB 一句话主张)

> 在固定的 8 GB 端侧预算下,一个 bit 的价值取决于它花在权重上还是缓存(KV cache)上。现有的每-bit 分配器只优化「内存与精度的权衡」,没有把「量化后的反量化(dequant)吞吐代价」显式写进预算;而真实设备测量表明,低 bit KV 缓存常以 decode 吞吐为代价。我们把精度保持与 dequant 吞吐当作**双目标**同时建模进 bit 预算分配器,并锚定到真实 8 GB 消费级 GPU 的可用性,使缓存压缩不只是更省内存,而是每一瓦每一美元换到更多 token。

命名候选:DOKB(Dual-Objective KV Budget,精度-吞吐双目标缓存预算)。

## 二、方法论横向对比矩阵(DOKB vs 核心对手)

下表所有同行按已核实的 paper_ 工具返回结果描述;DOKB 为本稿拟增强主张,标注「本稿 + 拟新增」。

| 维度 | **MultiAlloc** (arXiv:2610.18642, preprint) | **KV Pareto** (arXiv:2512.01953, preprint) | **kv4** (SSRN 10.2139/ssrn.6941538) | **Oaken** (ISCA'25, DOI 10.1145/3695053.3731019) | **GAMMA** (arXiv:2605.18475, preprint) | **本稿 DOKB(拟)** |
|---|---|---|---|---|---|---|
| 优化对象 | 仅 KV cache 精度 | KV cache 量化 + 权重量化 + chunked prefill | KV cache 4-bit 实机测量 | KV cache 量化 + 定制硬件 | 仅权重混合精度 | **权重 + KV 联合 bit 预算** |
| 目标函数 | memory-accuracy | 总内存 × accuracy(Pareto) | decode 吞吐 × 精度(工作量依赖) | accuracy × performance(co-design) | budget 约束隐状态重建 | **精度 × dequant 吞吐(双目标)** |
| 是否显式建模吞吐代价 | 否 | 否(仅定性提 TPOT 改善) | 是(实测为重点) | 是(吞吐为目标) | 否(仅附录 B 吞吐评估) | **是(建模进预算分配器)** |
| 预算分配器(可求解) | profiling 引导静态分配 | 经验性 Pareto 前沿搜索 | 无(逐 workload 定量) | 算法 + 定制引擎 | 约束优化 + 整数指派 | **约束优化分配器(拟)** |
| 是否锚定 8 GB 消费级 GPU | 否(7B-32B 数据中心级) | 否(通用 7B+,edge 泛指) | 是(4 GB GTX 1650 Turing) | 否(加速器) | 否 | **是(本稿实测 A/B 设备)** |
| 实测量 vs 仿真 | offline profiling 实测 | **QDQ 仿真**插入误差 | 真机实测 | 真机 + 硬件 | 量化误差仿真为主 | **真机实测(本稿核心卖点)** |
| batch>1 decode 吞吐表 | 未测 | 未测(无端到端解码表) | 有(decode 深度 × workload 矩阵) | 有 | 附录 B 有 | **需补(拟新增)** |
| 相反证据 | — | — | 低 bit KV decode 比 f16 慢的方向证据 | 挑战 outlier 检测开销 | — | **正面回应 kv4** |

> 补充核验事实:
> - **KV Pareto 的 QDQ 仿真**:原文明说 KV 量化 "simulated by a quantization-dequantization (QDQ) process to insert quantization error",即精度/内存是靠误差仿真而非真机端到端运行测得的。这是它与本稿「真机实测」最本质的差异。
> - **Oaken 是真硬件方案**:采用 online-offline 混合阈值 + 定制 quant/dequant 引擎与存储管理单元,目标是高吞吐 LLM serving,不是 edge 固定预算下的 bit 分配器。
> - **kv4 的数值边界**:SSRN 无 open-access 全文,p_ 工具仅返回其摘要级结论(4GB Turing GTX1650 上 decode 深度 × workload 矩阵,tokens/sec 头条掩盖工作量依赖)。**12-50% 这一具体数值需作者取得原文后再核验,当前不写入主张。**
> - **GAMMA 是权重侧主线**:全局混合精度 bit 分配 + 约束优化,强调可跨预算复用得分、适用任意 budget——与本稿权重侧对标,但它不处理 KV cache 也不测吞吐。

## 三、DOKB 绝对优势定位(收窄后的差异化轴)

全局检索(rounds 1-5,覆盖 KV 量化、混合精度、硬件感知、权缓联合、边缘预算检索式)后,未发现**同时满足以下四条件的现成框架**:

1. 权重与 KV 缓存处于**同一个 bit 预算**内联合分配;
2. 把 **dequant 吞吐代价显式建模进预算分配**(而非只在别处定性提一句);
3. 锚定**真实 8 GB 消费级 GPU** 的可用性(能不能跑起来);
4. 用**真机端到端测量**验证(而非 QDQ 仿真或纯误差分析)。

最近的四位对手各只占了其中一部分:
- MultiAlloc:占 1(仅 KV,不含权重)、缺 2/3/4(无吞吐/无 8GB/精度为主);
- KV Pareto:占 1(权缓联合)+3(edge 表述但非 8GB)+缺 2/4(QDQ 仿真、无吞吐建模);
- Oaken:占 2/3(吞吐、但硬件加速器非预算分配器)+缺 1;
- kv4:占 3/4(真机 4GB)+缺 1/2,且**方向相反**——它恰恰证明了「naive 低 bit KV 牺牲吞吐」,是本稿最需要正面回应、也最能借力立论的反例。

一句话:**DOKB = 唯一把「精度-吞吐双目标」显式写进一个可求解 bit 预算分配器、并锚定到 8GB 消费级 GPU 真机测量的权缓联合方案。** 它站在 kv4 的反向证据上提出「双目标都赢」,这正是通信与其他对手缺失的那一跃。

## 四、争取「一次过 Q1 小修」的可执行路径

按 academic-reviewer 的 Blocking 口径,以下按「能不能确立中心 case」分层。黑色=必须补齐才算把 DOKB 立住。

### P0-必要(否则中心 case 不成立)
1. **诚实复测汇率 9.0×/13.3×(整改 R1-M1)**:单设备、匹配 bit 宽度、拆掉 KIVI 128 残差窗,重算「每 bit 价格」。若受控后仅 ~1.3×(此前 CI[-2.16,-0.84]),主动把卖点从「便宜 X 倍」改为「受控匹配下缓存略便宜 + 容量几何使缓存压缩成为 8GB 首选」——卖点从数值转向「能否跑起来」。
2. **修 ρ 语义(AUD-01)**:摘要/引言/贡献处把 ρ 从「可用份额」改回「不可用份额」的准确措辞,改词不改数。
3. **README/data 声明同步**:jsa\main.tex / 公开 README 的「JSA 拒稿 → 转 IoT-J」说明统一到 IEEE IoT-J 口径(投前一律清除投稿历史措辞)。

### P1-立创新(把 DOKB 做成可命名算法件)
4. **补 DOKB 方法节 + 伪代码**:明确目标 = 在固定预算 W+K ≤ B 下 argmin PPL,约束吞吐 ≥ 阈值;吞吐代价项显式含 dequant 的带宽/算子开销。
5. **补 SOTA 对照,同设备同 bit 拆残差窗逐打**:MultiAlloc / KV Pareto / GAMMA / KVTuner(+KIVI/KVQuant 基线),同一张真机表格含 **PPL 列 + tokens/s 列 + 8GB 可用性列**——同时打 a) 精度保持 b) kv4 的吞吐反例。
6. **补 batch>1 与端到端运行时基线(响应 R1-M4/R2)**:给一个已部署 LLM 运行时(非仅配置层)的基准解码 track,直接回应「cache 便宜被吞吐对冲」。

### P2-增强证据
7. 扩展 n=3(现 passkey n=5 信号过窄)。
8. 取得 kv4 原文,核清其 12-50% 的测量边界并逐点回应(当前只按摘要级结论处理)。

## 五、「一次过小修」的把握与诚实边界

- 若只做 P0(措辞+口径),风险是:降到 Major 可谈,但仍不足以命中 IoT-J 对**算法创新**的水位——这正对应 JSA 当年缺创新被拒的旧伤。
- 若 P0 + P1 都做(尤其把「双目标吞吐模型 + 8GB 真机」立成可命名算法件),则相对已核实的最强对手(MultiAlloc / KV Pareto / Oaken)有清晰的可辩护差异:它们要么不建模吞吐、要么非 8GB、要么是硬件而非分配器。这一版有合理的「一次过小修」把握。
- 诚实声明:① 对 MultiAlloc / KV Pareto / Oaken 只精读了方法/背景,未通读全实验细节;② kv4 数值待作者原文核验;③ 「DOKB」目前是拟新增算法件,尚未在稿件中出现——本节是**投稿前路线图**,不是已完成的投稿主张。
