# 上下文长度是否放大 KV 的代价？——否（实测）

> 2026-10-20。`src/eval/bit_cost_vs_context.py`
> 数据：`results/bit_cost_vs_context.json`

## 1. 假设

KV cache 是**逐 token** 量化的：上下文越长，被量化的元素越多，
误差可能在注意力聚合中累积。若如此，KV 的相对代价应随 L 上升，
而权重的代价与 L 无关。那么"总是压 KV"的政策就有一个**上下文长度边界**，
论文必须写出来。

先前的文献支持这个担心：语料库里的 KVarN（`lit/corpus.csv`）明确主张
"量化误差在自回归解码中逐时间步累积"。

## 2. 测量

固定总 token 预算（8 窗口 × L），扫 L = 512 / 1024 / 2048 / 4096，
分别测全部权重 4-bit 与全部 KV 4-bit 的相对 PPL 增幅。

| L | 总 token | 权重 4-bit | KV 4-bit | 权重/KV |
|---|---|---|---|---|
| 512 | 4,096 | +33.02% | +6.71% | 4.92 |
| 1,024 | 8,192 | +32.56% | +5.43% | 6.00 |
| 2,048 | 16,384 | +34.60% | +5.49% | 6.30 |
| 4,096 | 32,768 | +37.87% | +6.85% | 5.53 |

## 3. 结果：假设不成立

- **KV 的代价几乎不变**：6.71% → 6.85%，跨度 **0.14 个百分点**
- **权重的代价反而波动更大**：32.6% → 37.9%，无单调趋势
- 比值稳定在 **4.9–6.3** 之间

所以在这台设备、这个模型上，**KV 量化的代价不随上下文长度累积**。

## 4. 这意味着什么

1. **政策不需要加边界条件。** 论文 §6.3 的"压 KV、留权重"在 512–4096 全范围内成立，
   不必写"但长上下文时可能反转"这种防御性的话。
2. **一个与文献的张力**：KVarN 主张误差在 decode 中累积，但在**困惑度**上
   我们没有观察到与上下文长度的交互。可能的解释是：
   - 它测的是长链推理任务的准确率，不是 PPL；
   - 累积发生在**生成**过程（每步都重新量化），而我测的是**一次前向**的 PPL。
   这两种设置不同，不能互相否证。已在论文里如实写成"没有以 PPL 形式显现"。

## 5. 局限

- 只到 4,096。更长上下文（16k、32k）可能不同，但受显存限制未测。
- 权重侧在 L=4096 略高（37.9%），可能是窗口内容差异而非长度效应；
  未做交叉验证（同一批文本的不同切分）。
