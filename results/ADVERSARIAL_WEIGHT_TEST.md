# 对抗性测试：调强权重量化器，结论是否翻转？

> `python src/eval/adversarial_weight.py`
> 数据：`results/adversarial_weight.json`
> 语料同前（2000 篇摘要，6×1024 窗口），基线 PPL 44.545

## 1. 为什么要做这个测试

"一个比特花在 KV 上更便宜"这个结论，最容易被攻击的点是：**我们的权重量化器是朴素 RTN**，
而 GPTQ/AWQ 在 4-bit 上接近无损。如果换成强量化器，权重成本可能掉到 KV 之下，结论就翻了。

所以我先把权重量化器在手边能调的维度上尽量调强，看能否翻过来。

## 2. 结果

| 权重量化器 | PPL | 相对增幅 | 判定 |
|---|---|---|---|
| RTN g=128 sym（原设置） | 48.59 | +9.08% | 高于 KV |
| RTN g=64 sym | 51.22 | +14.98% | 高于 KV |
| RTN g=32 sym | 52.28 | +17.37% | 高于 KV |
| RTN g=32 asym | 49.47 | +11.06% | 高于 KV |
| **RTN g=16 asym** | **47.61** | **+6.87%** | **高于 KV，但边际小** |
| KV 4-bit（实测参照） | 47.03 | +5.58% | — |

**排序在所有变体下都保持**（权重始终更贵），但边际从 **1.63× 缩到 1.21×**。

## 3. 一个反直觉的附带发现

**更细的分组反而更差**（g=128 → 9.08%，g=32 → 17.37%）。

正常预期是分组越细误差越小。这里相反，可能的原因：
- fp16 存储的 scale 本身被量化，组越小、scale 越密，scale 的表示误差占比越高；
- 组内元素少时，个别离群值会把该组的 scale 拉大，其余元素分辨率下降。

**这不改变主结论，但说明"更细分组一定更好"是错的**，值得在论文里作为一句观察。
（也可能是我实现的问题，已标注为待查。）

## 4. 结论必须改写

原表述：

> "一个比特花在 KV 上比花在权重上更划算。"

这个表述**过强**。真实 GPTQ/AWQ 有可能把 4-bit 权重压到 5.58% 以下（文献报告 7B+ 模型 4-bit 接近无损，
0.6B 上未必）。改成：

> **"在量化器强度可比的前提下，KV cache 不比权重更脆弱——4-bit 下 +5.6%（KV）vs +6.9~9.1%（权重）。
> 因此把 KV 固定在 16-bit、只压权重的做法缺乏依据。"**

这个表述仍然反直觉、仍然有实测支撑，但**不依赖"KV 一定更便宜"这个可能翻转的排序**。
它只主张"两侧应当被同等对待并一起分配"，而这恰好就是本文的方法。

## 5. 对论文的修改

1. §5.4 标题从 "A bit is cheaper in the cache" 改为 **"The cache is not the fragile side"**
2. 表注加一行：强量化器（GPTQ/AWQ）可能进一步降低权重成本，故只主张"可比强度下不更差"
3. Limitations 增加：未用 GPTQ/AWQ，排序的边际（1.2×）在更强权重端量化器下可能消失
4. 保留"求解器不动权重"这个结果，但把解释从"KV 更便宜"改为"在当前可用量化器下，动 KV 的收益/代价比更好"
