# 一个比特的价格：权重 vs KV（实测，真实权重）

> ⚠️ **v2 更新（19:00）**：下列数字已用 **48 个窗口**（此前 6 个）重测，并加了配对 bootstrap 95% CI。
> 旧点估计 32.33% / 5.58% 已被 34.65% / 5.35% 取代。新数据见 `results/bit_cost_ci.json`。

> 语料：`data/calib_arxiv.txt`（2000 篇 arXiv 摘要，575k token）
> 模型：真实 Qwen3-0.6B，fp16 基线
> 脚本：`src/eval/bit_cost_ci.py`（含 bootstrap CI）、`adversarial_weight.py`

## 1. 核心对比（48 窗口 × 1024 token）

| | 相对 PPL 增幅 | 95% bootstrap CI |
|---|---|---|
| **全部权重 4-bit**（RTN g=128） | **+34.65%** | [33.21, 36.11] |
| **全部 KV 4-bit** | **+5.35%** | [4.86, 5.87] |
| **配对差（cache − weights）** | **−21.76%** | **[−22.64, −20.88]** |
| 最强调参权重 4-bit（g=16 asym） | +6.97% | [6.41, 7.50] |
| 配对差（cache − tuned weights） | **−1.51%** | **[−2.16, −0.84]** |

**两个配对区间都排除零。** 即使把权重量化器调到最紧，cache 仍显著更便宜——但只差 1.5 个百分点。

## 2. 为什么加 CI 是必要的

6 个窗口的点估计已经指向同一方向，但**点估计无法回答"这个差异是不是噪声"**。
48 窗口下：
- 默认设置：差 29 个百分点，区间宽约 1.8 个百分点
- 最强调参：差 1.5 个百分点，区间 [−2.16, −0.84]，**宽度 1.3 个百分点，仍不含零**

## 3. 早期版本（保留以示演进）

| 位宽 | 全部权重量化 | 全部 KV 量化 | 谁更便宜 |
|---|---|---|---|
| 8 | +0.07% | 0.00% | KV |
| 4 | **+9.08%** | **+5.58%** | **KV，便宜 1.6×** |
| 3 | +94.86% | +25.23% | **KV，便宜 3.8×** |
| 2 | 崩溃（PPL 1.74M） | 崩溃（PPL 578） | 都不可用 |

**同等位宽下，压 KV 的精度代价始终小于压权重**，且位宽越低差距越大（1.6× → 3.8×）。

## 2. 这个结论直接反驳了文献惯例

现有做法是"权重优先、KV 保持 16-bit"（`lit/GAP_MATRIX.md` §2：108 篇里绝大多数把比特押在权重上）。
实测说反了：

1. **KV 每比特更便宜**（本节）
2. **长上下文时 KV 是更大的内存消费者**（`QWEN3_4B_8GB_LIMIT.md`：32k 时 KV 是 4-bit 权重的 2.7×）

两个因素叠加，结论很明确：**应优先压 KV，不是优先压权重。**
这与本文求解器在真实预算下给出的方向一致（`CAPACITY_TABLE.md`：小 ε 下 4060 选择"保 8-bit 权重、压 KV"）。

## 3. 必须声明的测量限制（否则结论会被过度引用）

1. **KV 量化器是朴素的**：逐通道 K / 逐 token V，**无残差窗口**。
   KIVI 等原论文在 2-bit 报告近无损，正是因为有残差窗口与分组缩放。
   所以我的 2-bit KV 崩溃**不代表 KV 量化在 2-bit 不可用**，只代表这个朴素实现不可用。
2. **权重端用了标准对称分组量化（group=128）**，这是 GPTQ/llama.cpp 的主流设置，比较对权重是公平甚至宽松的
   （`lm_head` 被保留在 fp16，而它是标定中**最敏感**的模块）。
3. 语料是摘要级（领域偏移），**绝对 PPL 不可与 WikiText 文献数值比较**；本节只用相对增幅，这是无量纲的。
4. 6 个窗口的噪声底约 0.12% 相对 PPL；本节所有差异（5.58% vs 9.08%）都远高于噪声。

## 4. 一个曾经出过的错（记录以示可信）

第一版把 K 与 V 的量化轴写反了（K 应沿序列轴取 scale，V 沿 head_dim），
结果 4-bit KV 报告 **+17170%**、3-bit **+418766%**——明显不可能是真实结果。
修正轴向后得到 +5.58%。**如果只看"数字变了"而不看是否合理，这个错误会直接进论文。**

## 5. 对论文的意义

这是全文最可操作的一条结论，且与领域惯例相反：

> 在 8 GB 设备上，一个比特花在 KV cache 上比花在权重上更划算；
> 而现有量化文献几乎把全部比特花在权重上。
