### 4.1 唯一 Blocking：R1-M1 —— 招牌汇率口径
"一个 cache bit 比一个 weight bit 便宜 9.0×/13.3×"受olves 三种混叠：(a) 权/缓两侧跨设备分测；(b) calibration 仅 2 段文本（恰为最有利值；升至 16 段 1.7B 权重成本 3.20%→5.96%）；(c) KIVI 保留 128-token 全精度残差窗。受控 tuned 对照仅 ~1.30×，配对 CI[−2.16,−0.84] 勉强排除 0。**若 margin 落 ~1.3×，建议改口径为"cache 略便宜 + 容量几何使其成首选"。**

### 4.2 主要 Major（Blocking No，须下一轮闭环）
- **R1-M2**：Jetson 容量列（ε=0.01 下 67k token）与 3.7× 价格移动出自解析模型，在 Edge 真机被实测证伪约 20×（预测 67k vs 实测 ~3k，4096 prefetch abort NvMap error 12）→ 改以两设备实测容量前沿为主数字。
- **R1-M3**："量化买容量非速度"只对 bnb/transformers 路径成立；稿件自身 llama.cpp q4_0 数据（prefetch 3.962 vs fp16 4.281；decode 115.7 vs 117.7）显示融合 4-bit 内核不慢 → 限定堆栈并注明融合内核是 parity。
- **R1-M4**："Both are wrong"缺已部署运行时端到端基线（对照仅配置层面）。R2-M2 + kv4 反向证据（低 bit KV dequant 持续 decode 慢 12–50%）同向施压。
- **R3-M1**：Data Availability "single command rebuilds the results"名不副实——run_all.py docstring 与 sec:repro 仅重建 figures/CSV/allocator 输入，不重跑测量；`--with-measurements` 仅加两个 CPU 侧 stage（一个硬编码 `C:/models/Qwen3-0.6B`）→ 改措辞 + 公开表级真实重测路径。
- **R3-M4**：docs/ENVIRONMENT.md 的 Jetson 节是空占位（"待 SSH 接入后填充"）+ 多个 checklist 未填（random seeds / nvpmodel / tegrastats logs / GPU temp-power / probe-JSON version）→ 异机 Jetson 复现者不知用哪个 JetPack/CUDA/power mode。
- **R2-M1**：原创性为"增量/整合型"（先例：KIVI 2402.02750 / KVQuant 2401.18079 / "KV Cache is 1 Bit Per Channel" 2405.03917 / RDKV 2605.08317 / MultiAlloc 2610.18642 / Don't Waste Bits! 2604.04722）→ 在 position 明示新增点是"度量"而非"结论"。
- **R2-M2 / R3-M3**：倍数三账本不符——摘要 9.0×/13.3× vs tab:bitcost 6.5×/5.7× vs WikiText2 10.9×/7.7× → 统一口径并标注。

### 4.3 Minor（节选，全部表述/文档层面）
passkey n=5 翻转风险 / tab:nospeed 两次均值 / Jetson prefetch 20% 噪声带 / WikiText 相对无标准 / "3.7×"摘要无推导 / GQA 普适句注 transformers 版本 / tab:headtohead 仅 L=4096 / **README 与稿件目标（IoT-J vs JSA）及 stage 数（16 published vs 17 local）对齐** / ρ 首个正式定义只在 method 方程 / 缩写密度高（TTFT/TPOT/GQA/KV/PPL/KIVI…）/ 补 repro checklist。

### 4.4 综合裁决
**Major Revision。** 方向性正确、诚实度高、工具链真实（GQA 32×/5.8×、ρ 3.15×、fp16 跨机一致、3.2× 打包、4B@32k 仅压缩 cache 可运行均为 **supported**）。但 R1-M1（招牌汇率）+ R1-M2（Jetson 容量）+ R3-M1/M4 + AUD-01 不闭环，核心论点不成立或无法独立复现。建议重心从"汇率 9–13 倍"调整为"受控匹配下 cache 仍略便宜 + 容量几何使 cache 压缩成为 8 GB 设备正确首选"。

## 6. 论文精读笔记 — academic-paper-reading（步骤 8）

落位：`paper/reading_notes.md`。要点：
- **In one sentence**：量化 KV cache 的精度代价比量化权重便宜约一个量级（0.6B 9.0× / 1.7B 13.3×），且两设备可用内存份额差 3.15×，因此"该压缩谁"的答案设备相关，无法对所有设备同时最优。
- **Problem**：反转四个默认假设——目标=容量而非吞吐；兑换率应抓权重而非 KV；标称显存≠可用预算。
- **Approach**：以容量为目标；用 GPTQ（权重）vs KIVI（cache）的 PPL 每 bit 成本作兑换率；实测 ρ=0.133（RTX4060 Laptop）vs 0.419（Jetson Orin Nano Super）；3 个输入 + allocator 导出设备专属安全上下文。
- **Results**：物话 KV heads 减 attention peak 32×、4k prefill 5.8×；容量表 1.65×（ε=0.01）；passkey 2-bit grouped 5/5 vs 0/5；B 侧 derived 列 <2% 误差；单命令复现 16 stages ALL OK。
- **How far evidence goes**：distinguish measured vs derived + assumption——**cache 跨层均匀铺开是 assumption（L380-388 明说）**、4-bit 走 ranking+rescale 对齐端到端。
- **Relation**：KIVI / MixKVQ / CocktailKV / KVTuner（cache）＋ GPTQ / RTN（weight）；novelty 详见 4.2 R2-M1。
- **Worth taking away**：投稿前必修 AUD-01（ρ 措辞）+ 跨语料相对 PPL 警示。
