# 求解器原型状态（W5–W6 的工作提前跑通了骨架）

文件：`src/alloc/dp_alloc.py`

## 已实现
- 权重 + KV **统一预算**的多选背包 DP（按字节桶，保留每个桶的 min-error 解）
- 逐层/逐 KV-head 的位宽选择 $\{2,3,4,8\}$
- regime-aware 时间模型：`eta_c(b)`（低位宽吃算力，因 dequant/无 INT4 TC）与 `eta_b(b)`（低位宽省带宽）
- 输出：字节占用、误差、时延、权重/KV 平均位宽直方图、交叉点 $b^*$

## 调试过程中发现并修掉的两个真错误（值得写进论文的 Method 讨论）

1. **α 共线陷阱**：若 prefill 与 decode 都写成 `bytes / B_eff`，两目标共线，α 自动消去，"regime"变成空话。
   → 必须引入 `eta_c(b)`，即低位宽的算力惩罚。这是本文与"只算字节数"的现有工作的数学分水岭。

2. **prefill 的 batch 不是 1**：prefill 一次处理整段 prompt，有效 batch ≈ prompt 长度。
   写成 batch=1 会让 prefill 永远落在带宽受限区，regime 永远不出现。我第一版就犯了这个错。

3. **KV 字节数重复乘 2**（K 和 V 各算一次后又乘 2），导致 32k 上下文被误判为 OOM。

## 当前仍是占位的部分（W5–W6 用真机标定替换）

## 一个必须提前想清楚的方法论问题
当前目标函数是"在误差约束下最小化时延"，其数学后果是：**只要内存装得下，最优解永远是最高位宽**。
所以量化只有在两种情况下才被选：① 显存真装不下（容量约束绑定）；② decode 带宽受限严重。
这不是缺陷，而是**正确的经济学**——它也意味着论文必须诚实地展示"量化何时无收益"（negative result 一节，见 `PLAN.md` §5）。
